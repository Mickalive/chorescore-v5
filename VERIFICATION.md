## Reprise du rouge Android et exploitation — 23 octobre 2026

- **Diagnostic réel du run `39998336273` (HEAD `76e36f86`)** : l'échec n'était pas un champ manquant. `scripts/android/verify-device.py` appuyait `KEYCODE_BACK` après `KEYCODE_ENTER` dans `add_member_at_creation`. Quand Entrée avait déjà fermé le clavier, ce retour sortait l'activité vers le lanceur ; les balayages suivants ouvraient le tiroir d'applications. La preuve `final-android.xml` téléchargée montre bien `com.google.android.apps.nexuslauncher` et non l'écran de groupe.
- Correctif : le script ne ferme le clavier que si `dumpsys input_method` indique qu'il est visible, attend l'apparition du chip du membre et vérifie que le formulaire est toujours ouvert. Les parcours suivants refusent explicitement de continuer si l'application a quitté le premier plan (`App left foreground during …`) au lieu de balayer le lanceur.
- `dismiss_system_dialog` ne masque plus aucune ANR générique : le dialogue doit venir d'`android`/`com.android.systemui` et nommer explicitement un processus système (lanceur/SystemUI). Une ANR nommant ChoreScore reste visible et fait échouer le scénario. Aucune assertion du parcours étendu n'a été retirée.
- Aucun `.pyc`/`__pycache__` n'est livré ; ils restent ignorés.
- **Sauvegarde/restauration réelles** : ajout de `scripts/backend/backup.mjs` (`VACUUM INTO` cohérent en WAL, manifeste SHA-256, copie des médias) et `scripts/backend/restore.mjs` (vérification d'intégrité, remplacement atomique, `--force` requis). `backend-tests/backup.test.cjs` crée un groupe et un média privé, sauvegarde pendant que la base reste ouverte, écrit une seconde photo, restaure et vérifie groupe, photo initiale et absence de la photo postérieure.
- **Déploiement reproductible** : `deploy/Dockerfile`, `deploy/docker-compose.yml`, `deploy/Caddyfile`, `deploy/.env.example`, `docs/DEPLOYMENT.md`. Le serveur n'est pas publié directement ; Caddy termine TLS, un seul processus écrivain, volume persistant, healthcheck et service de sauvegarde à la demande. Aucun secret n'est dans le dépôt.
- Commandes réellement exécutées : `python3 -m py_compile scripts/android/verify-device.py` OK ; `npm run typecheck` OK ; `npm test` **13 suites / 72 tests réussis** ; `npm run test:backend` **3 tests réussis** (dont sauvegarde/restauration) ; `docker compose config` résolu avec des valeurs factices ; `docker build -f deploy/Dockerfile` réussi ; conteneur lancé sans secret réel et `GET /health` a répondu `200 {"status":"ok"}`.
